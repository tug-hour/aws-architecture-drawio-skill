# 開発時の確認

aws-architecture-drawio 0.8.0は、旧版を残して別スキルを追加する案から、既存名を置き換える設計へ整理したもの。[設計判断](ADR-001.md)を参照。

通常作図の判断はSKILL.md、操作・表示確認・診断の条件とコマンドはreferences/authoring.mdを定義元とする。この開発確認を個々の作図へ課さない。

## 変更に応じた確認

生成・部品操作・診断・版情報を変更した場合は、対応する既存unitを実行する。全体の確認が必要な場合は次を使う。テストは標準ライブラリだけで実行し、描画や新規導入は行わない。

```sh
python3 -B -m unittest discover -s tests
```

変更した入力・描画処理・環境に影響がある場合だけ、新しい出力先へ描画して目視する。同じソース・入力・書式・環境の既存結果は再利用し、文書・配置場所・版番号だけの変更で再描画しない。通常作図の確認をunitや配布検査として再実行しない。

SKILL.mdの基本形式は既存skill-creatorのquick_validate.pyを使える。既存PythonにPyYAMLがなければ導入せず、frontmatter・命名・未完成箇所を読み取り確認し、validator未実施と区別する。参照リンクと標準ライブラリだけで閉じる依存も変更に応じて確認する。

旧版専用のテストは、その機能とともにGit履歴と退避した0.7.0に保持する。生成・部品操作・原本診断・版情報に適用できる既存テストは引き続き使う。今回の配置場所の変更では、コードの一致と既存のカタログ比較・合格結果を再利用する。

## 任意の実利用比較

同じCaseHub JSONを部品の元にし、同じモデル・effortを指定した独立コンテキストへ現行・候補の一方だけを渡す。新規タスクは両地域の分析経路bus→aggregateをbus→新SQS→aggregateに置換したDeskHub（78記号・80接続）、局所タスクはその追加SQSを両地域とも右へ100px動かし、入出線だけを調整する。同じ構成・PPTX採用値・編集可能性・地域間の配置統一を完成条件にする。

着手から初稿、構造確認、主担当による描画・目視までを記録する。局所修正は新規図の確認後に開始する。資料読み・設計・編集・生成・手戻りを含め、ツール待機・描画待ち・中断は分ける。観測できない通信・モデル内処理は分離不能とし、推測で純実作業時間を算出しない。主担当の共通作業と、新スキル開発・計測準備の時間は図の比較と分けて報告する。

生成のみの秒数を総作業時間の代わりにしない。記号・接続数と追加・削除した接続を確かめ、文字変更だけを新規作成の証拠にしない。両者の成果物を同じ既存draw.ioで表示し、要求した経路とその周辺を確認する。交差数だけで合格にせず、必要な場合だけ既存診断を再利用する。

独立した担当者間のばらつきと単一事例の限界があるため、この一対だけで一般的な速度向上を断定しない。差が小さい場合は小さいと報告し、追加の測定を通常利用の必須条件へしない。原本・実行記録はリポジトリ外の新規フォルダに保存し、公開する比較結果には個人パスやローカル時刻の履歴を含めない。

[独立候補だった0.1.0・da10a59での過去比較結果](comparison.json)では、初稿まで現行48.56秒・候補34.04秒、構造確認まで67.07秒・57.17秒。目視完了までの実経過は298.43秒・292.29秒で、うち生成後の共通作業・描画待ち・確認が231.36秒・235.12秒を占めた。並行開発が含まれるため、新規作成全体の速度向上の証明には使わない。後から補った余白・整列の指針による効果は、この記録では測定していない。

局所修正は構造確認まで31.81秒・23.65秒、目視完了まで94.60秒・67.17秒。そのうち描画開始までの引き渡し時間は36.82秒・22.99秒だった。図の手戻りは現行1回・候補0回で、両者とも無関係なセルは保持した。候補に残る端点直線の目安警告2件は、原寸表示で矢じりと文字が明瞭なことを確認し、追加の迂回を要求しなかった。診断は同じ判定を保持しており、検出を削除して得た結果ではない。

## 0.9.0候補の操作入口と規則分担

[設計判断](ADR-002.md)と[比較結果](batch-comparison.json)を参照。操作の条件・コマンドはreferences/authoring.mdを定義元とする。通常作図には検査を追加しない。規則データ・部品操作・一括生成を変更した際は既存unitと追加した回帰を一度実行し、同じ結果をPRまで再利用する。

比較は現行0.8.0と候補の一式を別担当・別領域で使う。同一モデル・Effort、元JSON、追加接続課題、描画環境を揃える。資料読みから描画・目視・修正までを含め、生成秒数だけを速度改善の根拠にしない。共通担当の引き渡し待ちや比較準備は条件別の作業と分け、分離できない時間は未分離と記す。新規図の確認前に局所図を生成した試行は、局所の独立した総時間比較には使わない。

今回の比較は実行機能を含むパッケージ同士で、指示単独のA/B/C比較ではない。スキル本文だけの効果、一般的な速度向上、全体自動配置の優劣は結論づけない。確認のためだけに同じ検査や描画を繰り返さない。
