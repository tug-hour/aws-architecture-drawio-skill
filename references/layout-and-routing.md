# 配置と経路

新規作成と繰り返し更新では、採用した配置・経路を[drawio/1のJSON](input-format.md#通常作図のdrawio1形式)へ保存する。既存のdraw.ioだけを修正する場合は直接編集を続けられる。列やAZの並びは実際の所属と通信を読み取りやすくするために選び、配置の都合でサービスや接続を追加しない。

## 配置の基本

draw.io XMLの座標はpx、カタログの寸法はptで、1 pt＝4/3 pxである。`mxGraphModel`に背景色と`adaptiveColors="none"`を指定する。既存の図を編集する場合は、その構造を引き継ぐ。

- `native-catalog.json`のshapeが標準図形IDである。サービスはカテゴリ色の外形と白い標準図形を重ね、内側の記号を外形の70%の領域に縦横比を保って置く。リソース・汎用はサービス用の背景を付けず、カタログの寸法とテーマ色を使う。カタログにない記号も既存ライブラリで確認して使える。
- 枠、記号、文字を別セルにし、包含枠には子セルを所属させる。子の座標は親からの相対位置である。線のparentは両端に共通する最も内側の枠とし、共通枠がなければルートに置く。
- 接続はsource・targetを実際の端点へ結ぶ。手動経由点はmxGeometry内のArrayに置ける。必要なら上下左右の接続点を使い、アイコン、ラベル、見出しとの重なりを避ける。下辺を使う場合も、下に置いたラベルを通過させない。
- ラベルと用途説明は読み分けられるように置く。表示に不要な技術IDや、枠と重複するAZ名を足さない。

## 新規作成と既存図の改修

新規作成では、依頼の構成・テーマに合う[既存JSONの部品](input-format.md#構成例の再利用と更新)を再利用する。PPTXの適用値は初稿のスタイルへ反映し、新しく採用するサービスの提供地域・接続方式に不確かな点があれば配置前に確認する。

所属枠と機能間の主要経路を整理したら、全体の詳細を決め切る前に初稿を生成する。再利用できる部分が多い場合は、それらを組み合わせて全体初稿を先に作る。配置に不確かさがある場合だけ、接続の多いノードを含む代表的な処理列を部分初稿で試し、細部を詰める前に全体へ展開する。サービス名・短い役割・枠見出しの領域と、複製・戻り・監視の通り道を確保し、接続先の順序に合わせてポートと配線順序を選ぶ。候補の比較が必要なら既存の経路診断を使い、局所修正を重ねる前に処理列の順序を見直す。生成・比較・描画の条件とコマンドは[rendering.md](rendering.md#jsonを更新元にする場合)に従う。

複数リージョンに共通する構成は、片側の代表配置を基に展開し、枠内の相対配置と処理方向を揃える。リージョン間配線も含めて配置を調整し、複製線を短くするためだけに片側を反転しない。共通サービスから各地域への接続が大きく迂回する場合は、内部配線の局所調整を重ねる前に、地域内の相対配置・内部配線を再利用しながら、共通サービス・地域枠・各地域の入口となるサービスの位置関係を見直す。地域枠の移動や共通サービスの中央への集約も候補とする。実際の構成・役割の違いは残し、明示的に固定された配置は維持する。

改修では、JSON管理中ならJSON、直接編集中なら既存原本を基準とし、変更するノード・文字・線と、その移動先や経路に接する周辺を対象にする。無関係な位置・経路・接続点は維持する。移動は親の相対座標とラベルを含めて扱い、移動ノードにつながる線の端点も更新する。局所案で改善しない場合に、その処理列や同じ所属枠まで範囲を広げる。draw.ioだけの既存図にJSON移行や全線の引き直しを要求しない。

どちらも、作図のたびに全図探索器や別の衝突判定器を作らず、既存の補助処理を再利用する。局所的な改善が止まったら、数値最小を求めて反復しない。自動最適化や最短経路を保証する手順ではない。

## 配置・接続点・文字領域を一緒に選ぶ

アイコンだけでなく、サービス名と役割の全文、枠見出し、矢じりの手前に必要な直線を含めて空間を確保する。文字の領域は別セルの実際の位置・寸法で扱い、役割説明を障害物から落とさない。文字サイズ・改行に対してセルの高さが不足する状態や、overflow=visibleによるはみ出しを、経路が空いていると解釈しない。文字幅を詰めるときも描画に必要な高さと余白を残す。役割説明は識別に必要な内容へ絞り、主要構成や接続を文章で代替しない。サービス名のPPTX規則と、役割説明の簡潔さを混同して新しい一律の行数制限を作らない。

AZなどの枠線も配線の空間に含める。必要な境界横断は、できるだけ直角に短く通す。枠線との重なりや見分けにくい並走は避け、AZ間を通す線には枠と判別できる隙間を確保する。離隔を一律の固定値やPPTXの必須数値規則にはしない。

- 接続先の相対位置と上下左右の空きを見て、直線・少ない折れ曲がりの候補から選ぶ。接続点はアイコン全体の線数ではなく、選んだ辺の入出線を合わせた本数で考える。1本なら中央、2本なら中央を挟む位置（約1/3・2/3）を出発点とし、本数が増えたときに使う範囲を広げる。少数の線を理由なく角近くへ寄せない。同じ辺では接続先の並びに揃え、別の線を同じ線分へ合流させない。
- 中央寄せは作図上の優先案であり、PPTXの固定比率や入力の制限ではない。既に直線で結べる位置を機械的に動かしたり、中央へ寄せるために交差・折れ曲がり・文字との重なりを増やしたりしない。空きが足りなければ別の辺やアイコン位置も比較する。明示された位置・接続点・経由点に固定の意図があれば維持する。
- 交差や迂回が残る場合は、その周辺で同じ所属枠内のアイコンの位置・順序を入れ替える案を比較する。リージョン間で対応する構成がある場合は、両側の処理列とリージョン間配線を一緒に検討する。アイコンの移動に伴い文字領域と接続点も見直す。所属、接続先、通信方向、PPTXの寸法・配色を変えない。
- 配線順序も候補に含める。主要経路や通れる場所が少ない線を先に確保し、後続線の交差・迂回が増えるなら順序を入れ替える。JSONの自動経路では既存の順序比較を使い、同じ候補を再計算しない。

直接編集した原本の候補は、任意の`drawio_routes.py`で描画前に比較できる。親からの相対座標とpxをptへ変換し、既存の経路判定を呼ぶ。図や経路は変更せず、独自の構成JSONも要求しない。自動配置・全候補の総当たり探索は行わず、配置と配線順序の候補は作図者が選ぶ。比較・確認の条件、計測範囲とコマンドは[原本の経路候補を比較する場合](rendering.md#原本の経路候補を比較する場合)を参照する。

部品の作成・複製・移動は[部品操作](parts.md)、旧形式の自動配置は[互換用の配置・経路](legacy-layout.md)を参照する。
