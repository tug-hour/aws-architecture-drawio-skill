# 配布・更新・復帰のリハーサル

lifecycle.pyは新規の専用領域で旧版と新版を共存させ、その領域のactive-release.jsonで実行対象を選ぶ。個人スキルへの設置、Codexの設定変更、CI有効化、外部公開、依存の導入は行わない。

```text
python3 <skill-dir>/scripts/lifecycle.py --old <old.zip> --new <new.zip> --output <new-isolated-dir> --runtime <approved-runtime.json> --profile <dedicated-profile>
```

各ZIPと同名の.zip.sha256が必要。取得元を確認した配布物だけを使う。checksum、CRC、内部manifest、パス、symlinkを確認してから展開する。既存領域への展開と上書きは拒否する。旧版の読込だけは版定義のない過去の配布物を警告付きで許容し、新版には版定義とmanifestの一致を必須とする。

旧版を選んでWeb図を実描画し、新版を選んで同じ旧入力を描画する。新版のプロジェクト機能も展開したプログラムから実行する。改変ZIPを拒否し、選択中の版が変わらないことを確認する。旧版に戻して、構成、配置、原本、SVG、PNGが最初の旧版実行と一致することを確認する。旧版のソースと全生成物は保管する。

選択ファイルはこのリハーサル専用で、Codexがどのスキルを読むかを切り替えるものではない。個人スキルへの設置と、新しいタスクでの発見・呼び出しは、配置先・影響を確認して承認後に別途検証する。既存環境以外での描画を保証しない。

失敗時は検証報告を保存し、合格として扱わない。実行結果はlifecycle-report.jsonと各描画のresult.jsonに残す。自動更新は行わない。

0.6.1では旧labelに用途説明が混在する入力を拒否する。同一入力での比較が成立するのは両版の入力規則を満たす場合だけである。移行が必要な入力は旧入力を保存し、descriptionへ分離した新版入力を別名で用意する。既存lifecycle.pyの同一旧入力リハーサルを0.6.1の移行検証済みと扱わない。0.6.0から0.6.1への更新・復帰リハーサルは未実施で、更新運用を開始する前に移行入力を含めて別途検証する。
