# 描画と確認

## スキルの生成物用の検証

通常作図は、依頼された図をdraw.ioで一度表示して確認する。日本語・使った記号・ラベルの切れ・重なり・接続方向・枠の所属を見て、必要な箇所だけ直す。指定テーマだけを作り、両テーマを納品する場合だけ両方を見る。図の小さな変更に、全カタログや無関係な図の検査を追加しない。

新規作成は全体と主要経路を確認する。改修は同じ原本・スタイル・描画環境の確認済み結果を使い、変更点と移動・配線の影響が及ぶ周辺を確認する。PPTXとの照合では、使った記号の寸法・色、12ptのアイコン／接続ラベル、サービス名の改行、枠と矢印を確認する。矢じりは[native-rules.md](native-rules.md)の採用値を使い、接続方向が明確で、潰れや線・文字との重なりがないことを確認する。「前の図と同じ」は適合の証明ではない。図の題名・節見出しとアイコン／接続ラベルは区別する。文字領域を小さくしただけで重なりが解消したとは判断しない。

ブラウザ実測、画像の再書き出し照合、検査レポート、unit、全受け入れ検証は通常作図の必須条件ではない。JSON管理ではJSONから生成した原本を確認する。直接編集版では元JSONとの一致を納品条件にしない。画像が必要ならdraw.ioの画面または既存CLIで一度書き出し、その同じ画像を確認する。

変更した線とその周辺では、所属するAZ枠を含め、境界横断と枠沿いの並走を区別し、枠と配線が見分けられることを確認する。経路警告がないことだけで離隔を確認済みにはしない。リージョン間の共通構成の配置を変更した場合は、対応する両側の相対配置・処理方向と、その間の配線も確認範囲に含める。構成・役割の違いに必要な配置差と、明示された固定配置には、一致を要求しない。

CLIの一例（既存draw.ioと既存の専用profileを使い、新しい出力ファイルを指定する）：

```sh
test ! -e "<new-diagram.svg>" &&
"<drawio>" --disable-update --user-data-dir="<dedicated-profile>" --export --format svg --theme light --embed-svg-fonts false --output "<new-diagram.svg>" "<diagram.drawio>"
```

PNGが必要ならformatをpngにし、SVG用のembed-svg-fonts指定を外す。原本の背景・配色は固定し、mxGraphModelにadaptiveColors="none"を指定する。CLIのtheme lightはエディター側の色変換を防ぐための指定であり、暗い背景の原本もその色で書き出す。

## JSONを更新元にする場合

新規作成・繰り返し更新では[drawio/1形式](input-format.md#通常作図のdrawio1形式)を使う。既存Pythonの標準ライブラリだけで原本を生成でき、draw.io・ブラウザの起動、計測、経路診断はこのコマンドでは行わない。

```sh
python3 -B "<skill-dir>/scripts/build_drawio.py" \
  --input "<drawing.json>" --output "<new-output-dir>"
```

`<skill-dir>`は使用するスキルのルート、`<drawing.json>`は更新したJSON、`<new-output-dir>`は未作成の保存先とする。構成例には`<skill-dir>/examples/servicehub.json`を指定できる。入力と既存出力は上書きしない。新規フォルダに`architecture.json`・`diagram.drawio`・`report.json`を保存する。`status=authored`は原本の生成完了であり、描画確認済みではない。reportの秒数は生成処理の時間で、配置の検討や表示・目視は含まない。

JSONを更新する際は、変更する要素と必要な接続だけを直して、同じコマンドを別の出力先へ実行する。生成した`diagram.drawio`を既存draw.ioで開き、上記の生成物用手順に従って変更箇所と周辺を確認する。入力・スタイル・生成処理・描画環境が同じ未変更部分には、既存の目視結果を再利用できる。共通スタイルや親の移動が及ぶ子要素は変更範囲に含める。無関係な図の再描画、通常unit、旧形式用run.pyによる再生成は追加しない。

経路の比較が必要な場合だけ、次節の既存診断へ変更前後の原本を渡す。通常生成では変更のないセルもXMLへ書き出すが、配置・経路の探索や再割り当ては行わない。

## 原本の経路候補を比較する場合

交差・迂回・文字との重なりが調整を難しくしている場合だけ使う。既存Pythonの標準ライブラリだけで読み取り、描画・図の変更・設定変更は行わない。候補ごとに別名で保存した原本を渡す。1ファイルでも確認でき、比較のための独自JSONや全候補の書き出しは不要である。

```sh
python3 -B <skill-dir>/scripts/drawio_routes.py <before.drawio> <candidate.drawio>
```

保存された直交経路・接続点とセルの文字領域を使い、`routing.py`の衝突・再侵入・線分共有・端点直線・接触・包含枠通過の判定を再利用する。各線の衝突等は最初の指摘を返す。座標・距離はpt。結果には原本のSHA-256、ページごとの解析した接続ID、交差・折れ曲がり・長さ、指摘、未解析要素を返す。指摘は確認補助であり、終了コード0は読み取り・解析を実行できたことだけを示す。読み取り不能は2。既存の生成・厳密検証の判定と終了コードは変えない。

ロックや接続不可の指定だけでは、アイコン・図形を障害物から除外しない。背景として除外するのは、頂点の子ではない最背面の矩形で、全要素を囲み、ページ背景と同色・枠線なし・文字なし・接続不可で、線の端点にもなっていないものだけとする。包含枠と非表示のグループ、線自身の端点とその文字を持たない装飾子は従来どおり除外し、文字は障害物に残す。

CLIの通常出力はセルごとの`topology`を省略し、比較結果・経路ID・数値・指摘・未解析部分を残す。内部比較データが必要な場合だけ、上のコマンドに`--details`を付ける。Pythonの`inspect_xml`・`compare`の返却内容は維持する。

`same_topology`はセルID・親・接続先・矢印の指定、`same_route_coverage`は解析した接続IDの一致を示す。どちらかがfalseなら、接続欠落や未解析部分を減点せずに数値だけで優劣を決めない。一致しても意味・色・図形・文字の一致や適合の証明ではない。

文字領域は保存されたセル寸法であり、実際の改行・フォントの計測ではない。プレーンテキストの保存高さが明示された文字サイズ×行数より小さい場合は、はみ出しの可能性を`unresolved`へ記録する。これは下限との比較であり、指摘がないことも実際の文字領域の正しさを保証しない。原本や障害物の寸法は自動変更しない。自動経路、曲線、回転、図形周囲への接続点投影、枠への接続、子を持たず包含・横断の意味が不明な枠、線に追従する文字などは推測せず`unresolved`に残す。キャンバス境界は検査しない。この解析範囲を図形の使用制限にしない。原本全体の数値は周辺への影響の確認に使い、警告ゼロや数値最小を完成条件にしない。

候補の比較は変更線と影響を受ける周辺の線・文字・枠を対象とし、文字や矢じりを潰さない候補の中で交差・長さ・折れ曲がりを比べる。交差数に加え、既存出力の`crossing_pairs`と原本の経路を参照し、解消した交差、新たな交差、位置だけ移った交差を区別する。交差を移しただけの案や、交差一つの解消に大迂回を要する案を無条件に採用しない。

配置と経路の候補を絞ってから、採用する図を上記の生成物用手順で表示する。変更した経路、その接続点・矢じりと周辺を同じ表示で確認し、候補の比較ごとに再描画しない。未変更部分は同じ原本・スタイル・描画環境に対する既存の目視結果を再利用できるが、移動で線や文字が近づいた範囲は変更範囲に含める。

互換用の配置表・厳密照合と実行環境は[互換用の描画手順](legacy-rendering.md)、スキル自体の変更・配布は[開発用の検証](development.md)を参照する。通常作図には追加しない。
